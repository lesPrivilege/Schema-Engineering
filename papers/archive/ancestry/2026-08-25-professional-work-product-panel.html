The gap
Demo ≠ Product

模型能完成节点，专业工作仍依赖专家在场

Dependence

Demo 依赖作者

专家知道该选什么材料、何时重试、哪里遗漏，以及什么可以交付；这些判断通常没有进入产品。

Effect

输出没有正式效力

一段回答可以很正确，却没有说明来源、完成状态、有效版本、批准权限和最终责任。

Attribution

失败无法归因

没有稳定的工作契约，团队无法判断失败来自模型、上下文、工具、评测，还是工作本身没有被定义清楚。

Prototype 展示“专家加模型能做到什么”；产品必须证明“专家离场后，团队仍能稳定完成什么”。

The source
Run the work first

不先要求专家写完整 SOP，让他们先把真实工作跑通

行业头部专家可以直接使用 frontier Agent 完成真实任务：选择材料、调整问题、调用工具、发现遗漏、修订结果并决定是否交付。

产品团队不把这段过程当作一次成功 Demo，而把它作为专业能力的 source material。

  1. select选择任务与真实材料
  2. steer调整问题、上下文与工具
  3. inspect发现遗漏、冲突与失败

The mechanism
Three nested chains

Work Contract 是工作场景的弱编译器

WHY “WEAK”

“弱”不是能力不足，而是拒绝伪造完整确定性：可稳定验证的义务交给系统，不可约的专业判断留给具备责任的人。

当前工作状态
  • 工作不会丢

    用户返回的是当前工作、有效成果和未完义务，不是重新寻找上一段 Chat。

  • 结果可以核

    重要结论可以回到来源；系统分得清“有依据”和“已经批准”。

  • 决定有人负责

    AI 可以查找、比较、起草和执行；什么正式生效，由具备 Authority 和 Accountability 的人决定。

Extension 自带 Definition of Done，而不是等模型自己宣布完成。

展开：Agent Extension 的逻辑内容
Context / resource policy、Artifact / evidence / completion contracts、Validators / Evaluators、Review / escalation、Recovery behavior 与 E2E release suite。它可以实现为 package、plugin、skill、workflow、service 或其他宿主可加载单元；物理形态不改变它的产品判据。

Failure attribution

先找失败发生在哪一层，再决定改进对象。生产 trace 不是自动训练数据，Review 也不会自动提升为正式规则。

Contract gap Evaluator gap Context gap Tool / interface accident Harness / recovery failure Model capability gap Institutional disagreement

先修定义、校验和环境，再判断是否需要训练模型。

展开：规则如何被提升
Capture first：先记录发生了什么；infer later：再推断它可能意味着什么；promote selectively：只有经过人工确认与回归验证的模式，才提升为 Contract、Validator、Evaluator 或 Environment 的新版本。

The product
Start at one boundary

不从宏大平台开始，从一条真实的承诺边界开始

1 task family+ 1 artifact+ 1 reviewer+ 1 formal commit boundary+ 1 E2E release suite
Accepted-work-product rate
有多少成果真正进入下一步工作，而不是只被生成或浏览。
Expert review time
专家是否从逐步驾驶转为关键节点裁决。
Recovery cost
中断、换人或换模型后，恢复当前工作的成本是否下降。

长期积累的不是 Prompt

  • Expert access
  • Compilation capability
  • Work semantics & contracts
  • E2E environments
  • Production failure distribution
  • Workflow integration & distribution
展开：Accepted work product 的定义
由具备相应 Authority 的 Reviewer 在预定流程节点接受、可以进入下一步业务流程、不需要实质性修改的 Artifact version。该指标应按任务族、风险、机构与 Reviewer 分层，并记录后续 reversal。

模型会替换，Prompt 会折旧。能够被验收、被复用、被组织接受的工作方式会留下。
